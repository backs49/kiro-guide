# 레시피: 버그 수정 스펙 작성

<span class="level">L2</span> Bugfix Spec으로 **"페이지 조회 시 마지막 페이지 데이터가 중복으로 나오는 버그"** 를 고쳐 봅니다. 핵심은 `bugfix.md`에 **바뀌면 안 되는 동작**을 먼저 적어 회귀를 막는 것입니다.

## 1. 재현 정보 모으기

스펙을 시작하기 전에 다음을 준비합니다.

- 재현 요청 예: `GET /api/products?page=4&size=20&sort=createdAt,desc`
- 기대 결과와 실제 결과
- 관련 로그 또는 실패하는 테스트

## 2. Bugfix Spec 시작

채팅에서 **Spec → Bugfix**를 고르고 상황을 설명합니다.

```text
상품 목록 페이지 조회에서 마지막 페이지에 이전 페이지 상품이 섞여 나와.
createdAt 이 같은 상품이 여러 개일 때 발생하는 것 같아.
#file 로 ProductRepository.java, ProductService.java 를 참고해 줘.
```

## 3. bugfix.md 검토

```markdown
# 버그: 상품 목록 페이지네이션 중복

## 현재 동작
- createdAt 값이 같은 상품이 페이지 경계에 걸치면, 다음 페이지에 같은 상품이 다시 나타나거나 일부 상품이 누락된다.

## 기대 동작
- 모든 상품은 전체 페이지를 통틀어 정확히 한 번만 나타나야 한다.

## 유지해야 할 동작 (변경 금지)
- 기본 정렬은 최신순(createdAt desc)이다.
- 응답 형식(content, totalElements, totalPages)은 바뀌지 않는다.
- size 최대값 100 제한은 유지한다.
- 기존 API 파라미터 이름은 바뀌지 않는다.

## 재현 방법
- createdAt이 같은 상품 25개를 저장하고 size=20으로 1~2페이지를 조회한다.
```

::: tip "유지해야 할 동작"이 가장 중요합니다
버그를 고치다가 정렬 기준, 응답 형식, 성능 특성이 바뀌는 일이 흔합니다. 이 절에 적은 항목은 설계·작업 단계에서 **회귀 테스트**로 이어지게 하세요.
:::

## 4. design.md / tasks.md

설계에서는 원인과 수정 방법을 확인합니다. 이 예에서는 정렬 키가 유일하지 않은 것이 원인이므로, `id`를 보조 정렬 키로 추가하는 방향이 자연스럽습니다.

```markdown
- [ ] 1. 재현 테스트 작성 (createdAt 동일 데이터 25건, 페이지 합집합 = 전체, 중복 없음) → 먼저 실패 확인
- [ ] 2. 정렬에 보조 키(id desc) 추가
- [ ] 3. 유지해야 할 동작 회귀 테스트 (기본 정렬, 응답 형식, size 제한)
- [ ] 4. 인덱스 영향 확인 (createdAt, id 복합 인덱스 필요 여부)
```

::: info Oracle을 쓰는 경우
Oracle에서도 정렬 키가 유일하지 않으면 페이지마다 순서가 달라질 수 있습니다. 실행 계획을 확인하고, 필요하면 복합 인덱스 추가를 설계에 포함하세요. DDL은 사내 반영 절차를 따릅니다.
:::

## 5. 실행과 확인

1. 작업 1(재현 테스트)을 먼저 실행해 **실패하는 것을 확인**합니다.
2. 작업 2를 실행하고 재현 테스트가 통과하는지 봅니다.
3. 작업 3의 회귀 테스트까지 통과하면 커밋합니다.

PR 설명에는 `bugfix.md`의 세 절(현재/기대/유지)을 그대로 요약해 넣으면 리뷰가 빨라집니다.
